# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Git rules

- NEVER commit or push. When work is ready, suggest a commit message and let the user run git themselves.
- Suggested commit messages must be a single line, with no Co-Authored-By trailer or any other Claude/AI attribution.

## Commands

- `docker compose up -d` — local Postgres 17.6 on **localhost:5433** (5432 belongs to piggygang-services)
- `cargo run -p indexer-admin -- migrate` — apply migrations; `-- seed [--dry-run] [--expect-unchanged]` — apply `config/collections.toml`; `-- backfill [--slug <slug>] [--limit N] [--das-only] [--check-images] [--expect-unchanged]` — the DAS backfill (needs `HELIUS_API_KEY`); `-- backfill-activity [--slug <slug>] [--address <mint>] [--drifted] [--limit N] [--rps N] [--reclassify] [--reprice-only] [--expect-unchanged]` — the ALG-622 archival crawl (`--drifted` repairs assets whose timeline contradicts their owner); `-- rarity [--slug <slug>] [--dirty-only] [--dry-run] [--expect-unchanged] [--verify] [--explain <address>]` — the ALG-627 rarity pass; `-- bench [--assets N] [--slug <slug>] [--dirty] [--clean]` — synthetic data + facet timings (the ALG-619 <100 ms evidence)
- `cargo run -p indexer-api` — API on `[::]:8080` (`PORT`/`HOST` env); needs `DATABASE_URL`, migrates at boot
- `cargo test --workspace` — DB tests are `#[ignore]`d (green without Postgres); `cargo test --workspace -- --include-ignored` runs them against `DATABASE_URL` (what CI does)
- `cargo clippy --workspace --all-targets -- -D warnings` and `cargo fmt --all --check` — CI gates (rustfmt defaults, no clippy config)

Toolchain is pinned by `rust-toolchain.toml` (1.90). Keep it in lockstep with the Dockerfile's `cargo-chef` tag and CI's toolchain when bumping.

## Architecture

Cargo workspace (`services/*` + `crates/*`), packages named `indexer-*`, all `publish = false`. Mirrors piggygang-services conventions (actix-web, sqlx). See README for the decision record (ALG-618): Rust + Helius Developer plan with Enhanced WebSockets ingest + Railway hosting.

- `crates/config` — env config. Missing var → default; present-but-unparseable → hard error (never `unwrap_or` a parse). `DATABASE_URL` is optional at parse time; binaries that need it call `required_url()` at boot.
- `crates/data-model` — Postgres schema (`migrations/`, embedded by `sqlx::migrate!()`), pool helpers, typed registry, seed loader, ingest cursors, facet queries, synthetic generator. Leaf crate: no dependency on `indexer-config` or `indexer-ingest`. Queries are runtime-checked `sqlx::query`/`query_as` (no `.sqlx` offline data, no DB at build time). Enums are `text + CHECK` in Postgres and `#[sqlx(type_name = "text")]` enums in Rust (`types.rs`).
- `crates/ingest` — the transport-agnostic ingest interface (`IngestSource`, `IngestEvent`, `SubscriptionSpec`) + `MockSource`, the `decode` module and the `ws` adapter. **Containment rule: pipeline code never matches on `RawPayload` variants** — only `decode` may, which is why it is always compiled rather than gated behind `ws`. `ws` (Helius Enhanced WebSockets) is a **default feature**, because `clippy --all-targets` does not enable non-default ones and a gated adapter would go unlinted. `grpc` = LaserStream is still absent; no stub modules before that issue. **This transport has no replay** — `fromSlot` is gRPC-only — so `ResumeFrom::Slot` is a floor and the consumer closes gaps by reconciling against DAS.
- `services/api` — actix-web binary. Routes register via `handlers::configure` so tests build the identical route table. `/health` is liveness-only by design (no DB ping — the Railway deploy gate must not depend on Postgres); `/ready` pings the DB. Both are outside `/v1` and outside the OpenAPI contract. **All eleven `/v1` paths are served**: ALG-625 the browse half, ALG-626 the detail half (`/nfts/{id}` + `/activity` + `/owners`, `/wallets/{address}/nfts`, `/collections/{slug}/activity` + `/holders`, `/search`). `handlers/v1/` is one module per contract tag. **Every SQL statement stays in `data-model`** (`browse.rs`, `facets.rs`, `stats.rs`, `nft.rs`, `timeline.rs`, `wallet.rs`, `search.rs`) — `services/api` holds DTOs, query parsing and HTTP concerns only. A `lib` target exists so the integration tests drive the real route table. `trait[Type]=Value` is parsed from the raw query string (`web::Query` collapses repeated keys and cannot express it) and accepts literal or percent-encoded brackets. Cursors are base64url `{v,s,k,f}`; `f` fingerprints an arbitrary scope list (collection+sort+filters+`q` for browse; asset/collection + the `kind` set for the feeds; wallet + `?collection=` for a portfolio), so a cursor replayed on another feed is `400 invalid_cursor`. The `-slot`/`wallet` examples in the contract carry no `f` and we emit one anyway — otherwise a `?kind=sale` cursor would be accepted on an unfiltered timeline and silently skip rows. The page query and the filtered `total` share one SQL fragment and one `facets::binds` call — that is what keeps the grid and the sidebar from disagreeing. CORS is allow-any (public, read-only, unauthenticated); `X-RateLimit-*`/`429` are deliberately not implemented (ALG-628). A disabled collection is a 404 — `registry::by_slug` returns disabled rows, and the `bench-*` fixtures live in the same table; the address-keyed endpoints apply the same guard as `c.enabled` inside their query, so a disabled collection's asset is invisible to detail, portfolio and search too. `/nfts/{id}` is the one endpoint deliberately outside the browse population: a `removed` or burned asset is still a valid page with valid history. An unknown wallet or search term is a `200` with an empty result, never a `404`; only a malformed address or parameter is a `400`. Boot validates `DATABASE_URL` (unresolved `${{…}}` references and `localhost` on Railway fail immediately), logs the sanitized target, retries connectivity with bounded backoff and runs migrations (advisory-locked in sqlx); a failing migration is fatal on purpose.
- `crates/das` — Helius DAS client (`getSlot`, `getAssetBatch` with 404 bisection, `searchAssets`) + the ALG-621 backfill. **Request/response only: never implements `IngestSource`** — that trait is the streaming interface, and a backfill's cursor lives in `backfill_state`, not `ingest_state`. Holds no SQL; every statement lives in `data-model::assets`, so the writer invariants are testable without a network and ALG-624 can reuse both halves. Hand-rolled over `reqwest` rather than the `helius` SDK (which drags in the whole solana-sdk tree and defaults to native-tls).
- `crates/activity` — the ALG-622 historical backfill: the archival crawl, the sale classifier and the venue registry loader. The one crate that needs the decoder *and* DAS at once, which is why it is neither (`crates/das` may not depend on `indexer-ingest`); takes `indexer-ingest` without the `ws` feature. **Holds no SQL** — every statement lives in `data-model::activity`, as in `crates/das`. Crawls with Helius `getTransactionsForAddress` (same `getTransaction` shape as the WS payload, so the *same* decoder; carries `blockTime`, so no `getBlockTime`) — **page until `data` is empty, never until the pagination token is null**. Querying the mint address alone misses escrow-era moves (a plain `spl-token` `transfer` names neither mint nor wallet), so the crawl expands to the asset's token accounts when the derived chain is not contiguous or does not end on the DAS owner. Pre-2022 token balances carry no `owner`, hence `DecodeContext::token_account_owners`.
- `services/admin` — `indexer-admin` CLI: `migrate | seed | backfill | backfill-activity | rebuild-ownership | bench`. The only place that writes the registry.
- `services/ingester` — `indexer-ingester`, the live pipeline (ALG-623). One `transactionSubscribe` over every tracked mint plus the Core collection address; decodes ownership from `meta.pre/postTokenBalances` (correct for plain `transfer`, `transferChecked` and CPI alike); writes through `data-model::activity`. Reconciles `(cursor, tip]` against DAS on **every** `Connected`. Classifies mint/transfer/burn only — a marketplace change is an honest `transfer` with the program ids in `details` for ALG-622 to reprice. Supervises itself and handles SIGTERM (it is PID 1 under the Dockerfile). **Tier 2's recovery floor is the candidate's own `last_activity_slot`, never the stream cursor** — the cursor is always ahead of anything the stream dropped, so using it made every scheduled sweep a no-op (`signatures=0`) while tier 1 kept patching `assets.owner`, and `integrity_owner_mismatch` climbed unboundedly. An asset with no recorded activity falls back to the cursor rather than 0: "never crawled" is `backfill-activity`'s job, not the sweep's, and 35% of tracked assets are in that state. The sweep also folds in `activity::drifted_assets` (exactly `integrity_owner_mismatch`), because once tier 1 patches an owner the asset stops disagreeing with DAS and would never be revisited; `backfill-activity --drifted` drains the same predicate on demand. **Reconciliation (ALG-624) also runs on a schedule**, and **everything that reconciles is a spawned task** — including the on-`Connected` one, which used to be awaited inline and stalled ingestion for the length of a sweep on a transport that drops what it cannot deliver; one at a time (a connect during a sweep rides the one in flight), aborted when the consumer's run ends. Cadence is `RECONCILE_TIP_INTERVAL_SECS` (30), `RECONCILE_INTERVAL_SECS` (3600) and `RECONCILE_DEEP_INTERVAL_SECS` (604800, the DAS backfill re-run); due-ness lives in `backfill_state.finished_at` so supervisor restarts cannot starve or double-fire it, and a job with no record is seeded rather than fired immediately. `schedule::TICK` is 10 s so the shortest configured interval is what governs. Every run writes its counters to `backfill_state` (`kind = 'reconcile'`/`'reconcile_tip'`/`'reconcile_deep'`); `progress.corrections` is the drift metric and uses the same definition as the backfills' `--expect-unchanged`, and `enumerate_ms`/`write_ms`/`recover_ms` say where a run's wall clock went. **The tip probe (`probe.rs`) is the freshness path**: one `searchAssets` sorted `recent_action` desc per collection filter (derived by `match`ing on `MembershipRule` and deduped — 3 calls cover 4 collections) instead of re-reading 17 820 assets to find the 5 that moved; it reads one page, never pages, and stops after 20 consecutive already-agreeing assets. It corrects state with `assets::apply_state` and rebuilds timelines through the same `recover_asset` the sweeps use — never a second implementation. **A state-only caller must use `apply_state`, never `upsert_batch`**, which writes `name`/`symbol`/`metadata_uri` unconditionally and would blank re-hosted metadata; the sweep's own state pass moved to it, which is what removed the per-sweep read of every stored metadata document. One rate-limited `DasClient` (`RECONCILE_RPS`, 10) is built in `main` and shared by the scheduler and the consumer's spawned reconcile — two limiters set to 10 would ask Helius for 20. The live path's client stays unthrottled; its `getBlockTime` retries a short backoff before parking, because a `confirmed`-fresh slot answering "Block not available" is *not yet*, not *never*, and believing it on the first try silently dropped a real transfer. A new Core mint's attribute hydration is spawned, not awaited, for the same reason the reconcile is.

### Data model rules

- **On-chain addresses live only in `config/collections.toml`, `config/seeds/*.mints.json` and `config/marketplaces.toml`** (the venue registry: marketplace program id → label, served verbatim as `ActivityEvent.marketplace`; only add a program you can attribute, since a guess reaches API clients as fact) — never in Rust, SQL or tests (tests use synthetic keys). Adding a collection = one TOML entry (+ mint list for a Token Metadata collection without a certified collection) → `seed` → backfill. No code.
- Membership is derived by Postgres from the registry row (`collections.membership_rule`: `core_collection` | `tm_collection` | `tm_allowlist`); pipeline code `match`es on `types::MembershipRule` — one arm per rule, never on slugs.
- The browse/facet population is `collection_id = $1 AND membership_status = 'member'` — burned assets included (the UI greys them); only `supply`/`holders` exclude burned. Every query over the population applies exactly that predicate.
- Migrations are forward-only and never edited once merged (sqlx checksums). Expand-only across a release: Railway keeps the old replica serving while the new one migrates, and the README rollback re-deploys an older binary against the newer schema.
- Ownership/activity writers use `data-model::activity::record`, which implements the contract in `migrations/20260829000400_activity_ownership.sql`: lock the asset, insert activity with `ON CONFLICT DO NOTHING … RETURNING`, mutate owner/history only when a row came back, flag `ownership_dirty` instead of applying out-of-order events. `ingest_state` is written only on `SlotCheckpoint`; `reset()` only with the ingester stopped.
- Backfill/live writers use `data-model::assets::upsert_batch`: every upsert carries a `WHERE … IS DISTINCT FROM …` guard so an unchanged row is a true no-op (no tuple, no `updated_at` bump) — that is what makes "re-running changes nothing" a checkable claim, so never drop it. `owner`/`owner_slot` move together under `EXCLUDED.owner_slot > assets.owner_slot`, stamped from a `getSlot` taken *before* the DAS call; the slot alone is never a reason to write. `attributes: None` means "not observed" (existing rows survive) and `Some(vec![])` means "observed and empty" (rows deleted) — that distinction is what lets a collection with a dead metadata host be filled in later by a TOML change alone. ALG-621 writes no `ownership_history` and never touches `image_status`.
- **Rarity (ALG-627) is scored over the browse population and the facetable trait types only**, with absence counted as a value: `score = Σ over facetable trait types of N / c(value-or-absent)`, summed in `numeric` (float8 addition is not associative — the same query gave three answers under three planner settings, which would make `--expect-unchanged` a coin flip), and `rank = row_number() ORDER BY score DESC, id` so it is a deterministic `1..N`. The formula is stated in `migrations/20260906000800_rarity.sql` and implemented once, in `rarity::RECOMPUTE`. A collection with no facetable trait type (Pig Mud, whose metadata host is gone) scores `NULL` rather than an N-way tie. Every writer that can stale a rank flags `collections.rarity_dirty` **from the SQL layer** (`assets::upsert_batch`, `set_membership_and_flag`, `sync_trait_facets_and_flag`) so the flag is transactional with the write; the ingester drains flagged collections every tick and the Core-mint path also re-ranks inline *after* its transaction commits. `sort=rarity` is rarest first, keyed on the **rank** (a float score would be truncated into the `i64` cursor), and rarity cursors carry `collections.rarity_version` so a re-rank is `400 invalid_cursor` instead of silently skipping rows — one mint moves 577 of 747 ranks.
- `openapi/v1.yaml` (ALG-620) is the frozen contract; the schema serves it, never changes it (`git diff --exit-code openapi/` must stay clean in any issue that implements it). OpenAPI 3.1, hand-written — there is no code-first generation and no OpenAPI crate. JSON fields are **camelCase**; enum *values* are the Postgres CHECK literals (snake_case). Every property is present with explicit `null` rather than omitted. `NftSummary`/`NftDetail` and the `/nfts/{id}/activity|owners` paths are named in the migrations — keep them. Additive changes only (new endpoints, new optional params, new response fields, new *request* enum members); anything else needs `/v2`. Lint with `npx @redocly/cli lint --config openapi/redocly.yaml`; mock with `docker compose up -d mock` (Prism on :4010). `openapi/` is dockerignored and absent from `railway.ts` watchPatterns — it is an artifact, not part of any image.

Ingest semantics (documented on the trait — keep them true): adapter owns reconnect; `Err` stream item is terminal; consumer persists `last_processed_slot` only on `SlotCheckpoint`; `ResumeFrom::Slot` is inclusive → at-least-once + signature-keyed idempotent upserts.

## Deployment

Railway (EU West Metal Amsterdam, region id `ams` — the short code, not the `europe-west4-…` form the docs show), deploys on push to `main` gated by CI (Wait for CI) and the `/health` healthcheck. Three services: `api` (`indexer-api`), `admin` (`indexer-admin`, `BIN=indexer-admin`, start command idles so `railway ssh` has a container to attach to, no healthcheck because it binds no port) and `ingester` (`indexer-ingester`, `BIN=indexer-ingester`, no healthcheck and no domain because it binds no port). One root `Dockerfile` builds any workspace binary via `ARG BIN` (default `indexer-api`) and installs it under its own name at `/usr/local/bin/${BIN}` (no generic `app`, no `ENTRYPOINT`; `CMD` execs `$APP_BIN`); a service that serves traffic must listen on `[::]:$PORT`. Secrets are env-only (`HELIUS_API_KEY`, `DATABASE_URL`) — never hardcode keys in source. `config/` ships in the **admin image only** (staged in the builder behind a `${BIN}` check, CI-guarded), so `seed` runs on Railway over the private network: `railway ssh --service admin -- indexer-admin seed --config /app/config/collections.toml`.

Project config is Railway **Infrastructure-as-Code** in `.railway/railway.ts` (needs Node >= 22 and `npm install railway`; `railway config pull` → `plan` → `apply`). Config-as-code (`railway.json`/`railway.toml`) is deprecated — new services cannot opt in at all and existing files stop being read on **2026-12-01** — so this repo has none; don't add one. Always baseline `railway.ts` from `railway config pull`, never hand-author it from scratch: IaC treats omission as deletion, so a file that doesn't mention the Postgres service invites the reconciler to delete it and its volume. Read every `plan` before `apply`, and never pass `--confirm-destructive` — it is a whole-run gate, not per-change. **A merge never applies this file**: no CI job runs the CLI and Railway's GitHub integration deploys images, so merging only redeploys existing services whose `watchPatterns` match. `plan` exiting 0 is the standing drift check; a variable set on a service but not declared in `railway.ts` shows up as a destructive `- Delete variable …`, so set it and declare it in the same change. **The IaC docs are an incomplete subset of the real option surface** — `build.builder`/`dockerfilePath`/`watchPatterns`, the whole `deploy` block (restart policy, cron, `sleepApplication`), `networking` and `github(..., { checkSuites })` (Wait for CI) all exist; the authoritative reference is the bundled `.d.ts` in `node_modules/railway`, not the website. There are no dashboard-only settings. Region ids here are short codes (`ams`), not the `europe-west4-…` form the docs show, and are unvalidated by the SDK.
