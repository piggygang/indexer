# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Git rules

- NEVER commit or push. When work is ready, suggest a commit message and let the user run git themselves.
- Suggested commit messages must be a single line, with no Co-Authored-By trailer or any other Claude/AI attribution.

## Commands

- `docker compose up -d` — local Postgres 17.6 on **localhost:5433** (5432 belongs to piggygang-services)
- `cargo run -p indexer-admin -- migrate` — apply migrations; `-- seed [--dry-run] [--expect-unchanged]` — apply `config/collections.toml`; `-- backfill [--slug <slug>] [--limit N] [--das-only] [--check-images] [--expect-unchanged]` — the DAS backfill (needs `HELIUS_API_KEY`); `-- bench [--assets N] [--slug <slug>] [--dirty] [--clean]` — synthetic data + facet timings (the ALG-619 <100 ms evidence)
- `cargo run -p indexer-api` — API on `[::]:8080` (`PORT`/`HOST` env); needs `DATABASE_URL`, migrates at boot
- `cargo test --workspace` — DB tests are `#[ignore]`d (green without Postgres); `cargo test --workspace -- --include-ignored` runs them against `DATABASE_URL` (what CI does)
- `cargo clippy --workspace --all-targets -- -D warnings` and `cargo fmt --all --check` — CI gates (rustfmt defaults, no clippy config)

Toolchain is pinned by `rust-toolchain.toml` (1.90). Keep it in lockstep with the Dockerfile's `cargo-chef` tag and CI's toolchain when bumping.

## Architecture

Cargo workspace (`services/*` + `crates/*`), packages named `indexer-*`, all `publish = false`. Mirrors piggygang-services conventions (actix-web, sqlx). See README for the decision record (ALG-618): Rust + Helius Developer plan with Enhanced WebSockets ingest + Railway hosting.

- `crates/config` — env config. Missing var → default; present-but-unparseable → hard error (never `unwrap_or` a parse). `DATABASE_URL` is optional at parse time; binaries that need it call `required_url()` at boot.
- `crates/data-model` — Postgres schema (`migrations/`, embedded by `sqlx::migrate!()`), pool helpers, typed registry, seed loader, ingest cursors, facet queries, synthetic generator. Leaf crate: no dependency on `indexer-config` or `indexer-ingest`. Queries are runtime-checked `sqlx::query`/`query_as` (no `.sqlx` offline data, no DB at build time). Enums are `text + CHECK` in Postgres and `#[sqlx(type_name = "text")]` enums in Rust (`types.rs`).
- `crates/ingest` — the transport-agnostic ingest interface (`IngestSource`, `IngestEvent`, `SubscriptionSpec`) + `MockSource`. **Containment rule: pipeline code never matches on `RawPayload` variants** — only a future decode module inside this crate may. Real transports (`ws` = Enhanced WebSockets, `grpc` = LaserStream) arrive in ALG-623 as optional-dep features; don't add stub modules or empty features before then.
- `services/api` — actix-web binary. Routes register via `handlers::configure` so tests build the identical route table. `/health` is liveness-only by design (no DB ping — the Railway deploy gate must not depend on Postgres); `/ready` pings the DB. Both are outside `/v1` and outside the OpenAPI contract. Nothing under `/v1` exists yet — ALG-625/626 implement it. Boot validates `DATABASE_URL` (unresolved `${{…}}` references and `localhost` on Railway fail immediately), logs the sanitized target, retries connectivity with bounded backoff and runs migrations (advisory-locked in sqlx); a failing migration is fatal on purpose.
- `crates/das` — Helius DAS client (`getSlot`, `getAssetBatch` with 404 bisection, `searchAssets`) + the ALG-621 backfill. **Request/response only: never implements `IngestSource`** — that trait is the streaming interface, and a backfill's cursor lives in `backfill_state`, not `ingest_state`. Holds no SQL; every statement lives in `data-model::assets`, so the writer invariants are testable without a network and ALG-624 can reuse both halves. Hand-rolled over `reqwest` rather than the `helius` SDK (which drags in the whole solana-sdk tree and defaults to native-tls).
- `services/admin` — `indexer-admin` CLI: `migrate | seed | backfill | bench`. The only place that writes the registry.

### Data model rules

- **On-chain addresses live only in `config/collections.toml` and `config/seeds/*.mints.json`** — never in Rust, SQL or tests (tests use synthetic keys). Adding a collection = one TOML entry (+ mint list for a Token Metadata collection without a certified collection) → `seed` → backfill. No code.
- Membership is derived by Postgres from the registry row (`collections.membership_rule`: `core_collection` | `tm_collection` | `tm_allowlist`); pipeline code `match`es on `types::MembershipRule` — one arm per rule, never on slugs.
- The browse/facet population is `collection_id = $1 AND membership_status = 'member'` — burned assets included (the UI greys them); only `supply`/`holders` exclude burned. Every query over the population applies exactly that predicate.
- Migrations are forward-only and never edited once merged (sqlx checksums). Expand-only across a release: Railway keeps the old replica serving while the new one migrates, and the README rollback re-deploys an older binary against the newer schema.
- Ownership/activity writers (ALG-622/623) follow the contract in `migrations/20260829000400_activity_ownership.sql`: lock the asset, insert activity with `ON CONFLICT DO NOTHING … RETURNING`, mutate owner/history only when a row came back, flag `ownership_dirty` instead of applying out-of-order events. `ingest_state` is written only on `SlotCheckpoint`; `reset()` only with the ingester stopped.
- Backfill/live writers use `data-model::assets::upsert_batch`: every upsert carries a `WHERE … IS DISTINCT FROM …` guard so an unchanged row is a true no-op (no tuple, no `updated_at` bump) — that is what makes "re-running changes nothing" a checkable claim, so never drop it. `owner`/`owner_slot` move together under `EXCLUDED.owner_slot > assets.owner_slot`, stamped from a `getSlot` taken *before* the DAS call; the slot alone is never a reason to write. `attributes: None` means "not observed" (existing rows survive) and `Some(vec![])` means "observed and empty" (rows deleted) — that distinction is what lets a collection with a dead metadata host be filled in later by a TOML change alone. ALG-621 writes no `ownership_history` and never touches `image_status`.
- `openapi/v1.yaml` (ALG-620) is the frozen contract; the schema serves it, never changes it. OpenAPI 3.1, hand-written — there is no code-first generation and no OpenAPI crate. JSON fields are **camelCase**; enum *values* are the Postgres CHECK literals (snake_case). Every property is present with explicit `null` rather than omitted. `NftSummary`/`NftDetail` and the `/nfts/{id}/activity|owners` paths are named in the migrations — keep them. Additive changes only (new endpoints, new optional params, new response fields, new *request* enum members); anything else needs `/v2`. Lint with `npx @redocly/cli lint --config openapi/redocly.yaml`; mock with `docker compose up -d mock` (Prism on :4010). `openapi/` is dockerignored and absent from `railway.ts` watchPatterns — it is an artifact, not part of any image.

Ingest semantics (documented on the trait — keep them true): adapter owns reconnect; `Err` stream item is terminal; consumer persists `last_processed_slot` only on `SlotCheckpoint`; `ResumeFrom::Slot` is inclusive → at-least-once + signature-keyed idempotent upserts.

## Deployment

Railway (EU West Amsterdam, region id `europe-west4-drams3a`), deploys on push to `main` gated by CI (Wait for CI) and the `/health` healthcheck. Two services: `api` (`indexer-api`) and `admin` (`indexer-admin`, `BIN=indexer-admin`, start command idles so `railway ssh` has a container to attach to, no healthcheck because it binds no port). One root `Dockerfile` builds any workspace binary via `ARG BIN` (default `indexer-api`) and installs it under its own name at `/usr/local/bin/${BIN}` (no generic `app`, no `ENTRYPOINT`; `CMD` execs `$APP_BIN`); a service that serves traffic must listen on `[::]:$PORT`. Secrets are env-only (`HELIUS_API_KEY`, `DATABASE_URL`) — never hardcode keys in source. `config/` ships in the **admin image only** (staged in the builder behind a `${BIN}` check, CI-guarded), so `seed` runs on Railway over the private network: `railway ssh --service admin -- indexer-admin seed --config /app/config/collections.toml`.

Project config is Railway **Infrastructure-as-Code** in `.railway/railway.ts` (needs Node >= 22 and `npm install railway`; `railway config pull` → `plan` → `apply`). Config-as-code (`railway.json`/`railway.toml`) is deprecated — new services cannot opt in at all and existing files stop being read on **2026-12-01** — so this repo has none; don't add one. Always baseline `railway.ts` from `railway config pull`, never hand-author it from scratch: IaC treats omission as deletion, so a file that doesn't mention the Postgres service invites the reconciler to delete it and its volume. Read every `plan` before `apply`, and never pass `--confirm-destructive`. **The IaC docs are an incomplete subset of the real option surface** — `build.builder`/`dockerfilePath`/`watchPatterns`, the whole `deploy` block (restart policy, cron, `sleepApplication`), `networking` and `github(..., { checkSuites })` (Wait for CI) all exist; the authoritative reference is the bundled `.d.ts` in `node_modules/railway`, not the website. There are no dashboard-only settings. Region ids here are short codes (`ams`), not the `europe-west4-…` form the docs show, and are unvalidated by the SDK.
